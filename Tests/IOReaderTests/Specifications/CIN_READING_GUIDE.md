# cinの読み取り挙動

文字・数値・単語・行について、何を読み、何を入力に残すかのまとめ。表の `\n` は改行、`\r` はCRを表す。

## 前提

cinはストリームに設定を保持し、その設定によって同じ読取り操作の挙動が変わる。この資料では、Swift側との対応を考えるため、まず次の条件に固定して説明する。

| 項目 | この資料で固定する条件 | cinで変更できる内容 |
| --- | --- | --- |
| 入力範囲・locale | ASCII入力、classic locale | 空白の分類、数値の区切りなど |
| `skipws` | 有効：値の読取り前に空白を飛ばす | `noskipws`で飛ばさなくする |
| 整数の基数 | `dec`：十進 | `oct`、`hex`、`setbase(0)`による接頭辞判定 |
| `width` | 0：単語の文字数制限なし | `setw(n)`等で文字列の読取り幅を制限。数値には適用されない |
| `boolalpha` | 無効：boolを扱う場合は数値形式 | 有効にするとclassic localeでは`true`・`false`で読む |

これは比較の出発点であり、Swift側でも将来すべて固定するという最終仕様ではない。cinが設定を保持するモデルとSwift側のAPIモデルの違いを整理するための前提で、可変にできる項目はこの対応を基に検討できる。

`skipws`は通常の`>>`による読取りの設定。`get`や`getline`は先頭空白を飛ばさない。`width`は文字列の読取り後に0へ戻るが、基数・`skipws`・`boolalpha`の設定は保持される。設定を切り替えた観測は別記する。

ここでいう残入力は、次の読取りから見える論理的な残り。C++実装がOSから内部バッファへ先読みする量とは区別する。

classic localeで飛ばすASCII空白は、スペース・タブ・LF・CR・垂直タブ・フォームフィード。行だけに閉じず、必要なら改行を越えて次の値を読む。

## 型による読み方の選択

`cin` が入力を見て「文字か数値か」を推測するのではない。受取り先のC++型と選ばれる `operator>>` のオーバーロードが読み方を決める。

| 受取り先・操作 | 読み方 |
| --- | --- |
| `char`、`signed char`、`unsigned char` | 空白を飛ばして1文字だけ |
| `int` 等の整数型 | 数値として読める部分を解釈 |
| `double` 等 | 浮動小数の読取り規則で解釈 |
| `std::string` | 空白を飛ばし、次の空白までの単語 |
| `get(char&)` | 空白も含めて1文字 |
| `std::getline` | 空白を飛ばさず改行まで |

C++の `unsigned char` は数値ではなく、1文字として読み取る。

## 文字の読取り

`>> char` は先頭空白を消費してから1文字だけ消費する。単語全体を読んで先頭だけ返すのではない。

| 入力 | 1回目の結果 | 残入力 |
| --- | --- | --- |
| `ab` | `a` | `b` |
| ` a b` | `a` | ` b` |
| `1 2` | 文字の `1` | ` 2` |

連続して `>> char` すれば `ab` から `a`、`b` と読める。1文字取り出せた時点では、その直後がEOFかを確認するためだけの読取りは要らない。

## 整数の読取り

先頭空白、任意の符号、十進数字を読み、数値に含まれない最初の文字は残す。値の後ろの空白・改行も残る。

| 入力 | 結果 | 残入力 |
| --- | --- | --- |
| `12 34` | `12` | ` 34` |
| `12\n34` | `12` | `\n34` |
| `+12` | `12` | 空 |
| `-12` | `-12` | 空 |
| `0012` | `12` | 空 |
| `12x` | `12` | `x` |
| `12.5` | `12` | `.5` |
| `1e3` | `1` | `e3` |
| `0x10`（既定の十進） | `0` | `x10` |
| `010`（既定の十進） | `10` | 空 |

次の数値読取りが先頭空白を飛ばすので、普通の数値列では区切りを残しても使い方は変わらない。違いが表れるのは、文字読み・行読みを混ぜる場合。

符号なしでも符号を受け付ける観測がある。今回の32bit `unsigned int` では `-1` が `4294967295` として成功した。

## 浮動小数の読取り

小数点・指数を解釈する。整数と同じ「数字の連続」だけでは実装できない。

| 入力 | 手元のlibc++での結果 | 残入力 |
| --- | --- | --- |
| `1.25 rest` | `1.25` | ` rest` |
| `.5` | `0.5` | 空 |
| `1.` | `1` | 空 |
| `1e3` | `1000` | 空 |
| `1.2.3` | `1.2` | `.3` |
| `12z` | `12` | `z` |
| `1e`、`1e+` | 失敗 | 空 |
| `12x`、`12abc` | 失敗 | 空 |
| `nan`、`inf` | 失敗 | 入力全体 |
| `0x1p2` | `4` | 空 |

これは保存済みのlibc++実測。数値候補の文字を収集する段階と、その候補を変換する段階があり、`strtod` で変換できた接頭辞だけを消費する方式とは一致しない。特に異常入力の結果を全C++実装で共通と断定しない。

## 単語と行の読取り

`>> std::string` は先頭空白を飛ばし、単語直後の空白を残す。

| 操作 | 入力 | 結果 | 残入力 |
| --- | --- | --- | --- |
| `>> string` | ` abc def` | `abc` | ` def` |
| `>> string` | `abc\ndef` | `abc` | `\ndef` |
| `getline` | `  abc\ndef` | `  abc` | `def` |
| `getline` | `\nabc` | 空文字列、成功 | `abc` |
| `getline` | `abc` + EOF | `abc`、成功 | 空 |
| `getline` | EOFのみ | 失敗 | 空 |

`getline` はLFを消費するが結果には含めない。今回のmacOSで ` a b\r\nnext` を読むと結果にCRが残った。CRLF正規化とLF区切りは別の処理。

整数を `12\nabc` から読んだ直後に `getline` すると、残ったLFを読んで空行が返る。これはcinの自然な合成結果。

- `ignore(..., '\n')` は現在行の残りとLFを捨てる。
- `std::ws` は空白を連続して捨てるため、空行や次の行の字下げも消す。
- この2つは同じ操作ではない。

## 失敗とEOF：cin側の参考挙動

既定ではストリームに状態を記録する。`failbit` は読取り失敗、`eofbit` は末尾への到達、`badbit` は入力処理の重大な問題。設定により例外通知も可能。

- `12` + EOFは整数12の読取り成功。`eofbit` は立つが、この時点では `failbit` は立たない。
- 値を読む前にEOFに達すると失敗する。
- `x12` を整数として読むと失敗し、`x12` は残る。
- `+x12` では符号を消費して失敗し、`x12` が残る。失敗しても入力消費が巻き戻るわけではない。
- 範囲外の整数では数字列を消費して失敗し、後続の区切り等は残る。
- 失敗状態は後続の読取りにも影響する。`clear()` は状態を解除するだけで、不正な文字を捨てたり入力を巻き戻したりはしない。
- 失敗時の出力値は一律ではない。今回、数値変換失敗では0、範囲外では上限・下限、読取り開始前のEOFでは元の値が残るケースを観測した。
